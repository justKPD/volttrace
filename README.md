# VoltTrace

**Falsification-driven, margin-aware SiL validation of high-voltage energy management**

> An independent portfolio project. Every parameter, requirement and line of ECU code here is **synthetic**.
> It does not represent or reproduce any Mercedes-AMG or Mercedes-Benz system and has no affiliation with either company.

A test that passes by 0.5 V and a test that passes by 50 V are both "green" in a PASS/FAIL report. They are not the
same evidence. VoltTrace runs an 800 V performance-BEV energy-management function in a closed SiL loop, judges every
measurement against requirements written in **Signal Temporal Logic (STL)**, and reports *how much* margin each
requirement had. It then goes looking for the scenarios nobody wrote a test for.

```
scenario ─► driver ─► plant (vehicle · motor · Rint pack · thermal) ─► DBC-quantised CAN (faults) ─► EMS (SUT)
                              │                                                                       │
                              └──────────────── 25 channels @ 100 Hz ◄────── torque / friction ◄─────┘
                                                      │
                     STL robustness ◄─────────────────┼──────────► MDF4 (.mf4)  ·  JUnit  ·  JSON  ·  Markdown
                     PASS / FAIL / INCONCLUSIVE / VACUOUS + margin + first violation
                                                      │
                     falsifier (cross-entropy / random) ──► counterexample ──► new regression test
                     mutants (8 seeded bugs) ──► kill matrix = how good is the test suite?
```

## What it has found so far

These came out of the pipeline, not out of a plan:

| ID | How it was found | What it is | Status |
|---|---|---|---|
| **F-001** | STL margin: TC-003 passed with **+0.01** margin, verdict **INCONCLUSIVE** | The undervoltage guard **limit-cycles at ~1 Hz** against the 20 ms BMS frame on a cold, aged pack | fixed (margin now +0.54) |
| **F-002** | **Falsifier**: no hand-written test caught it | Regen on an aged pack (R ×1.7) at ~90 % SOC overshoots **815 V within 30 ms**, before the reactive 805 V guard sees the next BMS frame | open, tracked as a regression test, fix planned (predictive state-of-power limit) |

## Results (seed-fixed, regenerated by CI)

**Mutation kill matrix.** Eight seeded bugs; a mutant is killed when a requirement fails on it but not on the clean SUT:

| Mutant | Seeded bug | Killed by |
|---|---|---|
| M01 | cold-cell factor computed but not applied | TC-007 (REQ-HV-012) |
| M02 | charge limit read from the discharge SOC map | TC-002 (REQ-EM-005) |
| M03 | friction brake ignores the rate-limited regen | TC-001, TC-004, FZ-003-CX (REQ-EM-006) |
| M04 | CAN timeout calibrated in ms, compared in s | TC-005 (REQ-FS-008) |
| M05 | thermal derating ramp inverted | TC-004 (REQ-EM-007) |
| M06 | torque-rate limiter ×10 | TC-001, TC-004 (REQ-DR-009) |
| M07 | undervoltage guard sign error | TC-003 (REQ-HV-001) |
| M08 | regen fade at standstill removed | **survived**: only observable with drivetrain compliance (vehicle level), declared as such |

**7/8 killed, 7/7 of the mutants observable in SiL.** Two design lessons came out of building the matrix:
- **Protections mask each other.** The voltage guard hides a missing cold-power cap, and the cold cap keeps the guard idle.
  A new pack never exercises the guard, so TC-003 uses an aged pack (R ×2.0) and TC-007 a healthy cold one.
  Each protection is tested where the other cannot cover for it.
- **Thin margins are informative.** Two "passes" at ≈0 margin turned out to be one real limit cycle (F-001) and one
  STL subtlety (see *conditional margin* in [`docs/DESIGN.md`](docs/DESIGN.md)).

**SiL run on the clean SUT.** 8 tests, 24 requirement checks: 22 PASS, 1 vacuous, 1 FAIL. The failure is the
known open finding F-002, so the gate passes. One escalation candidate:
- TC-005 / REQ-FS-008: the CAN timeout reaction is declared `hil` because bus timing is abstracted in SiL.

**Falsification.**
- FZ-003 (regen): finds F-002. Random search needs 9 simulations, the cross-entropy method 2 (seed 1).
- FZ-001 (undervoltage, 48 sims): no counterexample; worst margin +0.42.
- FZ-002 (thermal, 24 sims): no counterexample; worst margin +0.42.

The single-seed random-vs-CEM comparison is anecdotal. A multi-seed benchmark is Phase 2.

## The pieces

| | |
|---|---|
| **Plant** | longitudinal dynamics, torque/power envelope, tyre limit, Rint pack (192s, OCV(SOC), R(T), ageing), lumped cell + inverter thermal |
| **CAN** | [`volttrace.dbc`](src/volttrace/data/volttrace.dbc): 4 messages, cycle times from the DBC. Signals quantised and saturated to their DBC encoding, checked against `cantools` encode/decode. Faults: timeout, delay, stuck, offset |
| **SUT** | SOC/cold power maps, thermal derating with hysteresis, stateful voltage guards, torque arbitration, regen/friction blending, rate limiter, CAN-timeout and plausibility diagnostics, state machine. Calibration in a separate [YAML](src/volttrace/data/ems_calibration.yaml), as an A2L dataset would be |
| **Requirements** | 11 STL requirements + 1 performance KPI, each with criticality, features and required fidelity: [`requirements.yaml`](requirements.yaml) |
| **Tests** | [`catalog/`](catalog): launch series, high-SOC regen, cold aged pack, hot track sprint, BMS timeout, sensor fault, cold healthy pack, plus one falsifier-generated regression test |
| **Artefacts** | ASAM **MDF4** measurement per run (the ASAM standard that CANape and INCA record; verified here with asammdf), **JUnit XML** for CI, JSON, Markdown |

## Quick start

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"

volttrace pipeline                       # static checks -> lint -> SiL run -> gate   (the CI entry point)
volttrace mutants                        # mutation kill matrix
volttrace falsify falsify/FZ-003_regen.yaml --strategy cem --seed 1 --emit catalog   # rediscover F-002
pytest -q                                # 27 tests: STL semantics vs brute force, CAN vs cantools, plant physics, end-to-end gates
```

Outputs land in `out/`: `pipeline.md`, `summary_baseline.md`, `junit_baseline.xml`, `results_baseline.json`,
`mdf/*.mf4`, `mutation_matrix.md`. CI publishes them as the `validation-evidence` artefact.

## What this project is and is not

- It **is** a working SiL-first validation loop with formal requirements, quantitative margins, falsification,
  mutation scoring, and industry file formats (DBC, MDF4, JUnit).
- It is **not** HiL. Mock-HiL with bus jitter, ADC noise and slot costs is Phase 3, and will be labelled as a mock.
- It does **not** use CANoe, CANape, INCA or ecu.test. It produces and consumes their open file formats.
- Motivation: the SiL-first e-drive test ecosystem described by Schaak, Sauren et al. (ATZelektronik 5/2025), and its open
  question of how to balance test time against resources. VoltTrace explores that question from first principles.

Design rationale, alternatives considered and roadmap: [`docs/DESIGN.md`](docs/DESIGN.md).
